Reality2 is a decentralised mesh protocol for trust groups — built for devices that come and go, on links that mostly fail, with no infrastructure underneath and nobody in charge.

Scroll, or use the arrow keys.

01 — THE PREMISE

Everything is built on a highly lossy and movable network where nothing can be assumed.

That is not a caveat at the end of the design. It is the first sentence, and every mechanism has to survive it: does this still work when frames are lost, peers have moved, and no assumption held?

02 — WHAT THAT FORCES

The same shape appears at every layer

  • Nothing below the endpoints promises anything. A bearer transmits, and only ever knows that it transmitted.
  • Loss is repaired by the party that noticed — end to end, never hop by hop.
  • Silence is ambiguous, always. Asleep, moved, dead and out of budget look identical from outside, so nothing is concluded from silence alone.
  • State that matters lives at the endpoints and survives arbitrary interruption.
  • Time is a local ruler, not a shared fact.

03 — HOW CONFIDENCE WORKS

Nothing is proven. Things are un-refuted so far.

Confidence is earned by surviving attempts to refute it, updated as evidence arrives, decaying without it — and held locally, with no consensus and no shared truth anywhere.

BELIEF

“This link works.” “This path delivers.” “This neighbour is behaving.” Probabilistic, local, decaying, never final.

PROOF

“This message belongs to the group.” One binary gate. Cryptography, not belief — it verifies or it does not.

Everything below the line is trustless shared mesh: a device forwards for devices it has never met, belonging to groups it cannot join, carrying ciphertext it cannot read. Everything above it is authenticated, and every consequential act is gated there.

05 — WHO TALKS TO WHOM

Three answers at once, because they answer different questions

Agents converse.
Groups permit.
Devices carry.

One message, vertically: the agent composes → the device addresses → the groups permit → the device delivers → the agent decides. Most confusion about systems like this comes from asking “what talks to what?” without naming the layer.

06 — TRUST GROUPS

Sovereign groups, and a ladder between them

A trust group is a flat set of devices sharing a cryptographic identity — no hierarchy inside it, no authority above it.

  • Same group. Members of one identity.
  • Entangled. Two groups holding a conditional agreement — scoped, levelled, and standing exactly as long as its conditions are met.
  • Unauthenticated. Still exists, still carries. The mesh is not a rung of the ladder — every device is in it.

07 — WHY IT READS AS SOCIAL

Your agents can talk with theirs to the degree your communities trust each other.

That is a human truth rather than a protocol detail, and it is the reason the intelligent-agents metaphor survives the security model instead of fighting it. An agent can always speak. What the relationship between communities sets is whether the far side acts.

08 — WHAT IT IS FOR

Small things, meeting briefly, without infrastructure

NO SERVER

No cloud in the path, no broker, no registry. Devices that have never met relay for each other.

CONSTRAINED

Designed to run on microcontrollers — kilobytes, batteries, radios that sleep.

TRANSIENT

Encounters are brief and unplanned. Membership is durable; links never are.

09 — WHERE IT IS

Version 0.8.0 · draft

The specification is written, and it is being built from

The standard is a document set an implementer can build a conformant implementation from — layer by layer, with worked examples and byte-exact test vectors. It is drafted, not ratified: it is under active development and clauses still move.
