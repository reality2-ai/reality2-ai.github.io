Reality2 Standard — FORMATS companion test vectors

Status: Derived, informative. Generated by tools/gen-formats-vectors.py; regenerated and byte-compared by the pre-commit hook, so this file cannot drift from its generator. Date: 2026-08-02.

⚠ NOT PART OF THE REALITY2 STANDARD. Companion vectors for REQUIREMENTS-FORMATS.md. Every entry states the conforming case and the case the obligation excludes, because 01-terminology.md 4.2 requires the excluded case and 4.3 requires it to be distinguishable. A vector that passes shows an implementation accepts a conforming input; it does not show it would reject a non-conforming one.

The test applied to every entry: name what it would reject. Where that cannot be named, the entry is not evidence for an obligation — it is a demonstration that the format exists, and it does not belong here.

Coverage is partial and stated rather than implied. These cover the byte-mechanical obligations — identity derivation, purpose strings, the CBOR profile, firmware identity, and the signature exemption. The Clause 7 document obligations are not yet covered, and FORMATS.md 8.1 carries that debt.

FV-001 — Extended wire identity: hive half from the identity key

Demonstrates: F-005 (FORMATS.md 3.3).

Conforming. key = 000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f hive half = 630dcd29 (SHA-256 of the key, bytes 0-3, big-endian; 0 reserved-value iterations)

Excluded — must be refused. the same key truncated LITTLE-endian = 29cd0d63

What this rejects that a positive vector alone would not: an implementation that reads the four bytes in the wrong order — it is wrong about the same bytes and never fails on a positive-only vector.

FV-002 — Reserved half forces iteration, and the iteration is stated

Demonstrates: F-007 (FORMATS.md 3.5).

Conforming. a key whose first derivation lands on 00000000 or ffffffff re-derives over key ‖ 0x01, and repeats until the value is not reserved

Excluded — must be refused. accepting the reserved value, or re-deriving over a different suffix (0x00, a counter, the value itself)

What this rejects that a positive vector alone would not: an implementation that iterates with any other suffix: it produces a legal-looking identity that no peer derives, so the failure appears as an unroutable device rather than as a format error.

FV-003 — Purpose string is exact ASCII, no terminator, no padding

Demonstrates: F-012 (FORMATS.md 4a.2).

Conforming. the byte sequence of the table entry alone, e.g. r2/v0/group/frame = 72322f76302f67726f75702f6672616d65

Excluded — must be refused. the same string NUL-terminated = 72322f76302f67726f75702f6672616d6500, or with a trailing newline

What this rejects that a positive vector alone would not: an implementation that terminates its strings by habit: both sides derive different keys and the failure surfaces as a decryption error, never as a naming error.

FV-004 — A purpose string not in the table is not used

Demonstrates: F-013 (FORMATS.md 4a.4).

Conforming. derivation refuses a purpose string absent from the table

Excluded — must be refused. r2/v0/group/frames (plural) — one character from a table entry

What this rejects that a positive vector alone would not: an implementation that accepts any well-shaped string: a typo becomes a silently divergent key rather than a refusal.

FV-005 — Deterministic encoding: shortest form and key order

Demonstrates: F-014 (FORMATS.md 4b.2).

Conforming. {1: 1, 2: "two", 10: h'0a'} = a30101026374776f0a410a

Excluded — must be refused. the same map with key 10 encoded as 18 0a (non-shortest head) = a30101026374776f180a410a

What this rejects that a positive vector alone would not: an encoder that emits a legal but non-shortest head: the map is semantically equal and the SIGNATURE OVER IT DIFFERS, which is the whole reason 4b.2 exists.

FV-006 — Deterministic decoding refuses what encoding forbids

Demonstrates: F-015 (FORMATS.md 4b.2a).

Conforming. a decoder accepts the bytes of FV-005

Excluded — must be refused. a decoder receiving the non-shortest form of FV-005 must REJECT it

What this rejects that a positive vector alone would not: a decoder that canonicalises on read: it then verifies a signature over bytes that were never signed, and one logical map acquires two byte forms.

FV-007 — Refusal, not repair

Demonstrates: F-016 (FORMATS.md 4b.2b).

Conforming. rejection is reported to the caller

Excluded — must be refused. silently re-encoding the input into canonical form and continuing

What this rejects that a positive vector alone would not: the repair path — indistinguishable from correct behaviour on every positive vector, and the reason 4b.2b is stated apart from 4b.2a.

FV-008 — Duplicate map keys are refused

Demonstrates: F-017 (FORMATS.md 4b.3).

Conforming. a map whose keys are distinct

Excluded — must be refused. a2016161016162 — key 1 present twice

What this rejects that a positive vector alone would not: first-wins and last-wins alike: two conformant readers disagree about the same bytes, and neither can tell.

FV-009 — Tags are refused

Demonstrates: F-019 (FORMATS.md 4b.4).

Conforming. a payload containing no CBOR tag

Excluded — must be refused. c06a323032362d30382d3032 — tag 0 over a text string

What this rejects that a positive vector alone would not: a decoder that passes tags through: the tagged and untagged forms carry the same value and different bytes.

FV-010 — Nesting deeper than the stated limit is refused

Demonstrates: F-020 (FORMATS.md 4b.5).

Conforming. a payload nested to the stated limit (at least 8, per 4b.5b)

Excluded — must be refused. nine nested arrays = 818181818181818180 against a stated limit of 8

What this rejects that a positive vector alone would not: a decoder with no limit at all — it accepts until it exhausts its stack, which is a denial of service rather than a parse error.

FV-011 — A value the hive cannot determine is ABSENT, not zero

Demonstrates: F-034 (FORMATS.md 5c.2).

Conforming. all three keys known = a30167657370333273330207035820000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f

Excluded — must be refused. sequence unknown encoded as 0 = a30167657370333273330200035820000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f

What this rejects that a positive vector alone would not: the placeholder: 0 reads as THE FIRST PACKAGE EVER to an operator comparing against an artefact, and absence is the only encoding that says this hive cannot state this.

FV-021 — The development trust group, derived end to end

Demonstrates: L5-110 to L5-117 (L5-trust-and-identity.md Clause 9.1a-9.1h).

Conforming. seed = 57 bytes US-ASCII, no terminator, no trailing newline, every byte in 0x20-0x79 (inside the 0x20-0x7E bound):

Reality2 development trust group - not for production use

seed bytes = 5265616c6974793220646576656c6f706d656e742074727573742067726f7570202d206e6f7420666f722070726f64756374696f6e20757365

group secret = SHA-256(seed) = 7ffcba77aa8afc962e32f9f42ebc500414a46bdffade96db18dab8baf7c8b3ac, taken as the RFC 8032 private seed

public half = cc9527cecd948b5bb97b0c10e5838dd2ca0960694f317e34ebfda924a5333163

wire group half (FORMATS 3.3) = 0e6c3b8c, non-reserved

Excluded — must be refused. two excluded cases, and they fail at different gates. (a) Non-ASCII: the ASCII hyphen replaced by an EM DASH (U+2014) is 59 bytes, not 57 — refused by 9.1h before it is ever hashed — and if hashed anyway gives 7ba43f04c58f4707883ea3c8d4e7b49d7f9ebdff1c639bd5b8c67449299a78a6 and the group identity cd42eec437b7fba46839336f1e64b16ca481239faec1420053f040924cd58597. (b) Valid ASCII, one character: production capitalised is still 57 bytes and still printable US-ASCII, so every cheap check passes — it gives ee1d7b1b62beca896140b1a28b8ccf26f20fa774cfb3a38cf8db16e692bd43dd, public key dd591464b4ffede0a2d778ece75883145b3e06d39a88a4c1a1e5fc120c318a53, and group half d6cb6c3e. Both are different groups and neither must admit.

What this rejects that a positive vector alone would not: the two failure modes are not the same and only one is cheap to catch: a non-ASCII substitution changes the LENGTH and dies at 9.1h, while a single valid-ASCII character passes every structural check and is caught only by the digest. A vector carrying only the first would leave an implementation that checks length and range looking correct. This is the transcription failure the clause exists to prevent, reintroduced by the clause itself. Both identities are stated so a reader can check the refusal against a value rather than against a description — and because on this artefact an absent result and a wrong one look identical in a report. The length check is the cheap gate: an em-dash is three bytes in UTF-8, and several editors produce one from a typed hyphen automatically.

FV-013 — The baseline conforming score, and the seam from source to canonical bytes

Demonstrates: F-077 (FORMATS.md 7.8.1).

Canonical encoding (Clause 4b), rendered from the same structure as the source above — one source, two derivations.

a7646e616d656b6c6576656c2d776174636865636c617373781f6e7a2e6578616d706c652e656e73656d626c652e6c6576656c2d776174636865706172747381a4646e616d65654c6576656c65636c61737378186e7a2e6578616d706c652e73656e74616e742e6c6576656c6b6175746f6d6174696f6e7381a2646e616d65646d61696e6b7472616e736974696f6e7381a1656576656e7464726561646b6465736372697074696f6e76486f6c647320746865206c6173742072656164696e676776657273696f6e65302e312e3068756e7369676e6564f56b6465736372697074696f6e745265706f72747320612074616e6b206c6576656c6e736368656d615f76657273696f6e63302e31

Verdict. MUST LOAD. This is the vacuity guard and the baseline: every negative below is this document with exactly one change, verified by the generator to differ in exactly one place. It carries unsigned: true (7.9.4b) because a score with neither a signature nor that declaration is refused (7.9.4a) — a baseline that would itself be refused gives every negative a second reason to fail.

What this rejects that a positive fixture alone would not: nothing on its own — but without it every refusal below could be a refusal for a baseline reason rather than for the clause it names.

FV-015 — Unresolvable versioned reference fails, and fails loudly

Verdict. MUST BE REFUSED WITH AN ERROR, attributed to 7.3.2; and 7.3.3 forbids substituting an absent value, so a load that succeeds with an empty part fails 7.3.3 specifically.

What this rejects that a positive fixture alone would not: the silent-empty path: a pre-migration consumer once emitted empty values for every migrated entry, caught only by a negative control.

FV-016 — A part declared not runtime-executable is not loaded

Demonstrates: F-081 (FORMATS.md 7.8.4).

Document as authored.

    class: 'nz.example.sentant.level'
    automations:
      - name: 'main'
        transitions:
          - event: 'read'
    runtime_executable: False

Verdict. The score is otherwise the baseline, so it is well-formed by construction; the RUNTIME MUST NOT LOAD that part, attributed to 7.8.4. A builder may still realise it.

What this rejects that a positive fixture alone would not: a runtime that treats every part as loadable: the score parses, the part runs, and a build-time contract is executed as though it were a program.

FV-018 — An action naming an undeclared plugin is refused

Demonstrates: F-102 (FORMATS.md 7.10.2).

What this rejects that a positive fixture alone would not: deferring the failure to run time, where the sentant silently discards a result event that never arrives (7.5.6) and the fault presents as a dead automation.

FV-020 — A merely absent signature field is not the unsigned exemption

Demonstrates: F-098 (FORMATS.md 7.9.4a).

Document as authored.

name: 'level-watch'
description: 'Reports a tank level'
class: 'nz.example.ensemble.level-watch'
version: '0.1.0'
schema_version: '0.1'

Verdict. MUST BE REFUSED, attributed to 7.9.4a — the baseline carries unsigned: true and this removes it, leaving a score with neither a signature nor a declaration.

What this rejects that a positive fixture alone would not: the fail-open reading: a stripped, truncated or corrupt score is otherwise indistinguishable from a local-development one and loads. The baseline is the vacuity guard for this pair — it carries the declaration and must load.
